Before you start

Fill this in before you open your first session with the Orchestration Starter Kit. Fifteen minutes. Nothing is sent anywhere. At the end, press Copy answers and paste the result into your first session.

"I don't know yet" is a complete answer. So are "none" and "not applicable". Write one and move on.

1. The work

e.g. an email you owe someone, a one page summary of something you already have, a document you have been putting off. Real, not a test: you will do this one with the agent at the end of setup.
Plain words. Assume the reader knows nothing about your field.
A rough answer is fine.

2. Where it lives

Needs to be: somewhere permanent, not a temp folder, not already full of other files, and ideally without apostrophes or spaces in the path.
A desktop app, a terminal, an editor extension.
Some programs hand a job to a separate worker with its own memory; others run everything in one conversation.
One for everything is the default. Make a separate copy when a different client or employer's material must not sit in the same folder.

3. The walls

Name the folders. Everywhere else stays read only.
Name actual folders or files. This is the one to be specific about.

4. Checking the work

Proofreading, a colleague who reads it, a fact check, a test you run, a checklist. Whatever you already do.

5. How you work

The tone that makes you stop trusting the answer, in your own words.
How you think, how you read, what you already know well.

6. Names

One rule: keep them clear of your subject matter, or the name collides with the vocabulary of the work. If your project is about bones, do not name one after a bone.

7. If you stop

The project folder copies across. Your conversation history with the agent generally does not.

8. Words

Nobody sees this but you and your agent.

Worth knowing before you open the session

Nothing to fill in here. Six things that cost other people time.

You can stop at any point, for no stated reason.
Most people need more than one sitting; it picks up where you left off. Stopping is not failing.
Rewriting beats patching, for anything written.
Edits to a draft leave new sentences inside old structure, with the seams showing; ask for a fresh version with the new information instead. Code and records are the opposite: there the small change is the point.
The checks passing is not the same as the work being right.
In one test, a system produced a problem describing a situation that cannot physically happen, and all six of its own checks passed it. Read the first real batch yourself.
Anything committed to version control is permanent.
If you run git init in a folder that holds someone else's material, that material is in the history for good: deleting it later does not remove it, and publishing the project exposes the whole history. Check the folder first.
You are the one steering.
The risk is not the agent taking over; it is you approving work you have stopped reading. Waving things through is the signal to slow down.
An agent has no sense of time passing.
It does not know it is late or that you have been at this for four hours, and it will keep handing you work. The stopping rule has to be yours.
Editing the wording. Click any heading, question, hint or note and type. Answer boxes are switched off while you edit. It saves as you type. When you are done, press Copy my changes and paste them back to whoever keeps the form.
